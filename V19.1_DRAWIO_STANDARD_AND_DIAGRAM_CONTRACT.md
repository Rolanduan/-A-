# V19.1 — Draw.io Standard and Diagram Contract

Status: **additive upgrade**. All conceptual / architecture / technical-route / evidence-chain diagrams in V19 shall follow this Draw.io standard. This does not invalidate existing textual design decisions; it standardizes their visual execution.

## 1. Scope

The following diagram classes must be created in Draw.io (diagrams.net) style, not as ad hoc PowerPoint-like illustrations:

1. **Systems Architecture**
2. **Technical Route**
3. **Evidence-to-Decision Architecture**
4. **Algorithm I workflow**
5. **Algorithm II workflow**
6. **Algorithm III workflow**
7. **Claim–Equation–Data–Figure–Manuscript chain**
8. **Release / reproducibility / quality-gate flow**

## 2. Draw.io style rules

### 2.1 Canvas and export
- Use white background.
- Native editable source: `.drawio`.
- Export: `SVG` and `PDF`.
- Primary page size: US Letter landscape for wide architecture diagrams; portrait for workflow diagrams if more readable.
- Minimum final readable font in export target: 12 pt equivalent.

### 2.2 Shape grammar
- **Rounded rectangle**: process / computational module.
- **Document shape**: input or output file.
- **Cylinder**: data store / dataset repository.
- **Hexagon**: decision or audit gate.
- **Parallelogram**: external source or imported official raw data.
- **Swimlane / grouped lane**: system layer (data, model, decision, paper, audit).

### 2.3 Connector grammar
- Solid arrow: actual computed data flow.
- Dashed arrow: audit / validation / review flow.
- Dotted arrow: conceptual influence or interpretation, not direct computation.
- Red or warning-styled connector: blocking gate / failure branch.

### 2.4 Color semantics
- Data source / provenance: muted blue-gray.
- Graph/routing modules: teal.
- Optimization modules: sand/gold.
- Risk/fairness modules: muted terracotta.
- Manuscript / communication modules: navy.
- Audit / gate / warning: gray plus red accent.

## 3. Diagram-specific requirements

### 3.1 Systems Architecture
Purpose: show the full research stack from raw sources to paper outputs.
Required lanes:
- Official data inputs
- Spatial preprocessing
- Graph computation
- Scoring and ranking
- Optimization / fairness / robustness
- Manuscript / atlas / release outputs
- Quality gates

Each connector must be labeled with at least one variable, matrix, or file object (e.g., `D_RF`, `K(T,τ)`, `a`, `rank.csv`, `figure_registry.csv`).

### 3.2 Technical Route
Purpose: show the research pipeline in chronological execution order.
Required numbered modules:
1. acquire official raw files
2. verify SHA256
3. build city geometry and youth proxy
4. build pedestrian graph
5. compute Algorithm I access kernel
6. compute M0 / controlled ablations / M1
7. compute Algorithm II optimization
8. compute Algorithm III fairness and resilience
9. compute LP/Pareto/evidence horizon
10. render GIS / charts / atlas
11. render paper and perform release audit

### 3.3 Evidence-to-Decision Architecture
Purpose: show how observed data, normative weights, counterfactual modules, and final recommendations are separated.
Required separation:
- Observed quantities
- Derived but observational metrics
- Counterfactual outputs
- Normative decision layer
- Communication outputs

### 3.4 Algorithm diagrams
Each algorithm diagram must contain:
- input set
- data structures
- key loop or computation
- output object
- exact audit outputs
- failure / blocking conditions

### 3.5 Claim-chain diagram
This must explicitly show:
`source manifest -> equation contract -> result CSV -> figure ID -> manuscript section -> release audit`.

## 4. Prohibitions
- No decorative icons unrelated to the science.
- No 3D blocks.
- No unlabeled arrows.
- No arrows that pretend a normative preference is an observed data flow.
- No generic “AI analysis” box without explicit role.

## 5. File naming
- `D19-01_systems_architecture.drawio`
- `D19-02_technical_route.drawio`
- `D19-03_evidence_to_decision.drawio`
- `D19-04_algorithm1_routing.drawio`
- `D19-05_algorithm2_optimization.drawio`
- `D19-06_algorithm3_fairness_resilience.drawio`
- `D19-07_claim_chain.drawio`
- `D19-08_release_quality_gates.drawio`

## 6. Manuscript use
The paper should include at most 2–3 compact Draw.io diagrams in the main body, with the rest placed in the technical atlas or reproducibility appendix. The main candidates are:
- D19-01 Systems Architecture
- D19-02 Technical Route
- D19-03 Evidence-to-Decision Architecture

## 7. Acceptance gate
A diagram is accepted only if:
- the editable `.drawio` exists,
- the exported `SVG/PDF` exists,
- all arrows are labeled,
- all major variables and file objects are named,
- it matches the actual V19 computational modules,
- it uses the prescribed style grammar.

This file adds execution standards. It does not assert that the Draw.io diagrams have already been drawn.
